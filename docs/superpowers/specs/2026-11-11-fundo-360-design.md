# Fundo 360°: design (fase 3 da mesa)

Data: 2026-11-11 · Status: aprovado para implementar · Branch base: `dev-jg` · Depende de: `2026-11-11-mesa-e-fundo-design.md` (fases 1 e 2)

## 1. Objetivo

O jogador usa uma **foto panorâmica 360°** como fundo: ela envolve a cena e **reflete nos dados de gema**, então a floresta (ou taverna, ou caverna) aparece no brilho dos dados. Fica salva na mesa e vai junto no `.glb` exportado.

## 2. Como está hoje

| Peça | Onde | Comportamento |
|---|---|---|
| Fundo de cor | `src/scene/Stage.tsx` | `<color attach="background">` |
| Fundo de foto/tema | `src/scene/Backdrop.tsx` | CSS atrás do canvas transparente (custo zero na GPU) |
| Reflexos | `Stage.tsx` | `<Environment resolution={256}>` com 3 `Lightformer`s (cubemap gerado uma vez) |
| Tipos de fundo | `src/scene/tableTheme.ts` | `color` · `preset` · `image` (+ `blur`, `dim`) |
| Exportação | `src/scene/tableFile.ts` | foto do fundo num plano oculto `fundo` dentro do `.glb` |

## 3. Decisões (respostas do backlog)

| Pergunta | Decisão |
|---|---|
| Substitui ou soma aos `Lightformer`s? | **Soma.** O panorama entra no cubemap junto com os `Lightformer`s (`EnvironmentPortal` do drei com `map` + os `Lightformer`s como filhos). Sem os `Lightformer`s os dados ficam apagados num panorama escuro |
| Formatos | **JPG, PNG, WebP e `.hdr`** (HDRIs como os do Poly Haven). `.exr` fica de fora (arquivos grandes, decodificação pesada) |
| Tamanho | Até 4096 × 2048 (maior é reduzido); proporção 2:1 obrigatória (tolerância 1,9–2,1). `.hdr` até 25 MB |
| Vai no `.glb`? | JPG/PNG/WebP **sim** (plano oculto `fundo-360`, como o `fundo` de hoje). `.hdr` **não** cabe no glTF; ao exportar, o app avisa e grava uma versão JPEG tonemapeada do panorama |
| Liga/desliga o reflexo | Sim: "Refletir nos dados" (padrão ligado) |

## 4. Requisitos

| ID | Requisito |
|---|---|
| F1 | Novo tipo de fundo **360°** no painel da mesa, ao lado de Cor, Foto e Tema |
| F2 | Aceita JPG/PNG/WebP 2:1 até 15 MB e `.hdr` até 25 MB; reduz para no máximo 4096 × 2048; proporção errada é erro em pt-BR |
| F3 | Ajustes: **girar** (0–359°), **brilho** (0,3–1,5), **desfoque** (0–0,4) e **refletir nos dados** |
| F4 | O panorama aparece atrás da mesa (`scene.background`, canvas opaco) |
| F5 | Com reflexo ligado, os dados refletem panorama + `Lightformer`s; desligado, só os `Lightformer`s (como hoje) |
| F6 | Trocar ou ajustar o panorama não recompila os shaders dos dados nem trava a animação; o cubemap é regenerado uma vez por mudança, entre animações |
| F7 | Exportar leva o panorama (JPG/PNG/WebP como estão; HDR convertido para JPEG com aviso); importar devolve o mesmo fundo |
| F8 | Desempenho: crítico do d100 com panorama 4096 × 2048 e reflexo ligado, p95 ≤ 20 ms na GPU de referência |
| F9 | Física e resultados não mudam |

## 5. Design técnico

### 5.1 Tema (`tableTheme.ts`)

Novo tipo: `{ kind: 'panorama'; image: Blob; format: 'ldr' | 'hdr'; rotation: number; intensity: number; blur: number; reflect: boolean }`, com `clamp` e validação como os outros. `fromExtras` aceita o tipo (sem o blob, que vem do nó `fundo-360`).

### 5.2 Carregar a imagem (`tableImages.ts`)

- LDR: `createImageBitmap` → `reduceImage` (já existe) até 4096 px de largura → `Texture` com `mapping = EquirectangularReflectionMapping` e `colorSpace = SRGBColorSpace`.
- HDR: `HDRLoader` (já incluso no three, `three/examples/jsm/loaders/HDRLoader.js`), import dinâmico para não pesar no carregamento inicial; reduzir se passar de 4096.
- Checar proporção depois de decodificar.

### 5.3 Cena (`Stage.tsx`, `Backdrop.tsx`)

- `Backdrop` não desenha nada para `panorama` (como para `color`).
- `scene.background = textura`, `backgroundRotation.y`, `backgroundIntensity`, `backgroundBlurriness` (o three r187 tem os quatro).
- Ambiente: trocar `<Environment>` por `<EnvironmentPortal resolution={256} map={reflect ? textura : undefined}>` com os mesmos `Lightformer`s; `environmentRotation` acompanha a rotação. O alvo de renderização do cubemap é o mesmo (só muda o conteúdo), então os materiais dos dados não recompilam. **Conferir isso na implementação** medindo `gl.info.programs` antes e depois de trocar o panorama.
- Regerar o cubemap só quando a fase for `hand` ou o showcase já tiver terminado (mesma regra do DPR em `docs/contexto/armadilhas.md`).

### 5.4 Painel (`ui/TablePanel.tsx`)

Aba **360°**: escolher arquivo, girar, brilho, desfoque, refletir nos dados. Texto curto: "Use uma foto panorâmica 2:1. Poly Haven tem HDRIs grátis."

### 5.5 Exportar e importar (`tableFile.ts`)

- Exportar: plano oculto `fundo-360` com a textura LDR (HDR → render tonemapeado num canvas 4096 × 2048 → JPEG) e `extras` com rotação, brilho, desfoque, reflexo.
- Importar: nó `fundo-360` → panorama; mesmas regras de limpeza e limites da fase 2.

## 6. O que acontece se der errado

| Situação | O app faz |
|---|---|
| Foto que não é 2:1 | erro: "A foto 360° precisa ter proporção 2:1 (ex.: 4096 × 2048)." |
| Arquivo grande demais | erro com o limite |
| `.exr` | erro: "Use .hdr, .jpg, .png ou .webp." |
| Panorama muito escuro | o brilho (F3) compensa; os `Lightformer`s continuam iluminando os dados |
| GPU fraca (SwiftShader) | panorama reduzido para 2048 × 1024 automaticamente quando o DPR inicial for o de software |
| `.glb` com `fundo-360` e sem `extras` | usa o panorama com ajustes padrão e avisa |

## 7. Testes

**Vitest:** validação do tema `panorama` (limites, proporção, formato); `fromExtras` com e sem os campos.

**Playwright** (uma rodada no fim): escolher um panorama 2:1 pequeno (fixture gerada) → `scene.background` é a textura; ligar/desligar reflexo muda a cor refletida num dado (pixel); girar muda o fundo; exportar → importar mantém rotação, brilho e reflexo; proporção errada dá erro. `__dice.table()` expõe `background: 'panorama'`, `reflect` e o número de programas de shader (para F6).

**Desempenho:** medir o crítico do d100 com e sem panorama (método rAF já usado), registrar na seção de medições desta spec.

## 8. Riscos

- **Recompilação** ao trocar o mapa de ambiente: mitigado por usar o mesmo alvo do cubemap; se ainda recompilar, compilar antes com `gl.compile` como a mesa importada já faz.
- **Memória:** 4096 × 2048 RGBA ≈ 32 MB na GPU, mais o cubemap; por isso o teto de 4096.
- **Conversão de HDR para JPEG** perde a faixa dinâmica no arquivo exportado; o original fica salvo no navegador.

## 9. Decisões em aberto (padrão adotado)

1. Aceitar `.hdr` (padrão: sim).
2. Reflexo ligado por padrão (padrão: sim).
3. Teto 4096 × 2048 (padrão: esse).

## 10. Ordem de construção

1. Tipo `panorama` no tema + validação + testes.
2. Carregamento LDR/HDR com redução e proporção.
3. Cena: fundo, rotação, brilho, desfoque; `EnvironmentPortal` com reflexo; checagem de programas de shader.
4. Painel.
5. Exportar/importar `fundo-360`.
6. Medição de desempenho e docs (`docs/contexto/mesa.md`).
7. **E2E só no fim**, uma rodada, depois de pedir horário à sessão principal.
